# 发版流程（v0.1.1 起固化为标准流程）

> 依据：v0.1.0 / v0.1.1 两次实际发版提炼。四仓纪律：本仓只放代码，安装包发布到 `Phoenix-DRX-releases`，公告数据发布到 `Phoenix-DRX-Opendata`。

## 流程总览

```
门禁全绿 → bump 版本 ×4 → commit 代码 → 写公告(Opendata) → push Opendata
        → push master → 打 tag v* + push tag → CI 自动构建发布 → 验收
```

## 第一步：门禁

```
npm run gate     # svelte-check 0错0警 + eslint + vitest 全绿才允许发版
```

## 第二步：版本号四处同步（缺一不可）

| 文件 | 位置 |
| --- | --- |
| `package.json` | 顶层 `version` |
| `src-tauri/tauri.conf.json` | 顶层 `version`（**应用与安装包的实际版本，CI 构建以它为准**） |
| `src-tauri/Cargo.toml` | `[package] version` |
| `src-tauri/Cargo.lock` | `name = "phoenix-drx"` 条目的 `version`（手动同步，避免 CI 首跑改动 lock） |

## 第三步：commit 代码

- 中文主题式 message，格式参照历史：`主题：要点 + 要点 + 要点`。
- `git status` 先盘点：**新功能文件常以未跟踪状态漏网**（v0.1.1 即有 8 个 `??` 新文件），必须 `git add` 明确列出，禁用 `git add -A` 盲加。
- 不 push、不打 tag 之前，本地再跑一次 `npm run gate` 兜底。

## 第四步：写公告（Phoenix-DRX-Opendata 仓）

本地仓位置：`E:\WorldModelGeneraor\Phoenix-DRX-Opendata`，编辑 `announcement.json`：

1. 顶层 `version` 递增 +1（客户端以此判断载荷有效）。
2. `killSwitch` 保持 `false`（仅官方紧急停用时置 true，公告视为空）。
3. 发布类公告**只保留最新一条**（替换上一版本的发布条目），`free-forever` 长期声明常驻，避免启动连弹多条。
4. 条目字段：`id`（`v0XX-release`）、`title`、`body`（平实中文，禁技术黑话）、`actionLabel` / `actionUrl`（指向发版仓 releases 页）、`date`（YYYY-MM-DD）。
5. commit + push Opendata（客户端三镜像拉取：raw → ghfast 反代 → jsDelivr，push 后即可被拉到）。

## 第五步：打 tag 触发发布（CI 自动完成以下全部）

```
git push origin master
git tag v0.1.X
git push origin v0.1.X
```

`.github/workflows/release.yml` 在 tag 上自动执行：

1. `verify`：check + lint + test（master push / PR 也跑）。
2. `build-windows`：`npm run tauri build`（需仓库 Secret `TAURI_SIGNING_PRIVATE_KEY` 更新签名）。
3. 生成 `latest.json` 更新清单（版本号取自 tauri.conf.json）。
4. 校验产物齐全（msi + nsis exe + sig + latest.json）。
5. `gh release create` 发布到 `65tiankehan/Phoenix-DRX-releases`（Secret `RELEASES_PAT`）。

## 第六步：验收清单

- [ ] GitHub Actions `release` 工作流全绿。
- [ ] 发版仓出现新 release，附件含 msi / setup.exe / sig / latest.json。
- [ ] 旧版本客户端「检查最新」能收到新版本（updater 走 latest.json）。
- [ ] 新版本客户端首启弹出 v0.1.X 公告 toast。

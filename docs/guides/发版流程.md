# 发版流程（v0.1.1 起固化为标准流程）

> 依据：v0.1.0 / v0.1.1 两次实际发版提炼。四仓纪律：本仓只放代码，安装包发布到 `Phoenix-DRX-releases`，公告数据发布到 `Phoenix-DRX-Opendata`。

## 流程总览

```
门禁全绿 → bump 版本(9 文件 10 行) → commit 代码 → 写公告(Opendata) → push Opendata
        → push master → 打 tag v* + push tag → CI 构建（含 Forge zip）→ 验收 → Forge 建版本
```

## 第一步：门禁

```
npm run gate     # svelte-check 0错0警 + eslint + vitest 全绿才允许发版
```

## 第二步：版本号九文件十行同步（缺一不可）

| # | 文件 | 位置 |
| --- | --- | --- |
| 1 | `package.json` | 顶层 `version` |
| 2–3 | `package-lock.json` | 顶层 `version` + `packages.""` 下的 `version`（**两行**） |
| 4 | `src-tauri/tauri.conf.json` | 顶层 `version`（**应用与安装包的实际版本，CI 构建以它为准**） |
| 5 | `src-tauri/Cargo.toml` | `[package] version` |
| 6 | `src-tauri/Cargo.lock` | `name = "phoenix-drx"` 条目的 `version` |
| 7 | `installer/installer-config.json` | 顶层 `version`（自研安装器的载荷版本） |
| 8 | `installer/src-tauri/tauri.conf.json` | 顶层 `version` |
| 9 | `installer/src-tauri/Cargo.toml` | `[package] version` |
| 10 | `installer/src-tauri/Cargo.lock` | `name = "phoenix-drx-setup"` 条目的 `version` |

**两条硬教训（都翻过车）**：

- 两个 `Cargo.lock` 里各有多处 `version = "0.2.x"`（属于别的 crate），**必须按 `[[package]] name = ` 块定位逐行改**，禁止全局替换、禁止 `-replace` 带 count。
- 这两个 lock 与 `installer-config.json` 都是 **CRLF**，必须字节级替换。用 `JSON.parse/stringify` 重写会重排格式（v0.2.4 出过 35 行假 diff、lock 从 128424 字节缩成 123327），用 PowerShell `Set-Content` 误写会把文件清成 0 字节（v0.2.3 出过）。

改完必查：`Select-String -Pattern '<旧版本号>'` 全仓应为 0 命中（`package-lock.json` 里 `minimatch "^10.2.2"` 这类依赖版本除外）。

## 第三步：commit 代码

- 中文主题式 message，格式参照历史：`主题：要点 + 要点 + 要点`。
- `git status` 先盘点：**新功能文件常以未跟踪状态漏网**（v0.1.1 即有 8 个 `??` 新文件），必须 `git add` 明确列出，禁用 `git add -A` 盲加。
- 不 push、不打 tag 之前，本地再跑一次 `npm run gate` 兜底。

## 第四步：写公告（Phoenix-DRX-Opendata 仓）

本地仓位置：`E:\WorldModelGeneraor\Phoenix-DRX-Opendata`，编辑 `announcement.json`（顶层键是 `version` / `killSwitch` / `announcements`，**不是 items**）：

1. 顶层 `version` 递增 +1（客户端以此判断载荷有效）。
2. `killSwitch` 保持 `false`（仅官方紧急停用时置 true，公告视为空）。
3. 发布类公告**只保留最新一条**（替换上一版本的发布条目），`free-forever` 长期声明常驻，避免启动连弹多条。
4. 条目字段：`id`（`v0XX-release`）、`title`、`body`（平实中文，禁技术黑话）、`actionLabel` / `actionUrl`（指向发版仓 releases 页）、`date`（YYYY-MM-DD）。
5. commit + push Opendata（客户端三镜像拉取：raw → ghfast 反代 → jsDelivr，push 后即可被拉到）。

## 第五步：打 tag 触发发布（CI 自动完成以下全部）

```
git push origin master
git tag v0.1.X
git push origin v0.1.X
```

`.github/workflows/release.yml` 在 tag 上自动执行：

1. `verify`：check + lint + test（master push / PR 也跑）。
2. `build-windows`：`npm run tauri build`（需仓库 Secret `TAURI_SIGNING_PRIVATE_KEY` 更新签名）。
3. 构建 DRX-Setup 壳 + 拼接载荷，产出 `*-installer.exe` 并签名。
4. 生成 `latest.json` 更新清单（版本号取自 tauri.conf.json）。
5. **打包 Forge 上架 zip**：`scripts/pack-forge.ps1` 产出 `Phoenix-DRX_<ver>_win-x64.zip`。
6. 校验产物齐全（msi + nsis exe + installer exe + sig + zip + latest.json）。
7. `gh release create` 发布到 `65tiankehan/Phoenix-DRX-releases`（Secret `RELEASES_PAT`）。

推送前先探网：`Invoke-WebRequest -Uri https://github.com -Method Head` 通不过就重试；`git push` 遇 `Connection was reset` / `Empty reply` 时改用 **`git -c http.version=HTTP/1.1 push`** 并循环重试 3–8 次（2026-11 起本机常态）。

## 第六步：Forge 上架包（CI 已自动产出）

Forge 的 Download Link **只接受 `.7z` / `.zip`**，填 exe 会报：

> The download link must be for a 7-zip (.7z) or ZIP (.zip) file. Please review our Content Guidelines.

CI 现在每版自动产出 `Phoenix-DRX_<ver>_win-x64.zip`（已随 release 一起发布），结构：

```
Phoenix-DRX/install-notes.txt                        安装说明（版本号与安装器哈希已替换）
Phoenix-DRX/Phoenix-DRX_<ver>_x64-installer.exe
```

本地要重打：`pwsh scripts/pack-forge.ps1 -Installer <*-installer.exe> -Version <0.2.X> -OutDir <dir>`
（说明模板在 `scripts/forge-install-notes.txt`，占位 `{{VERSION}}` / `{{SHA256}}`；脚本带条目自检，缺项直接抛错。）

**Download Link 用 zip 直链**：
`https://github.com/65tiankehan/Phoenix-DRX-releases/releases/download/v<ver>/Phoenix-DRX_<ver>_win-x64.zip`

## 第七步：验收清单

- [ ] GitHub Actions `release` 工作流全绿。
- [ ] 发版仓出现新 release，附件含 msi / setup.exe / installer.exe / 各自 sig / **`*-win-x64.zip`** / latest.json。
- [ ] `latest.json` 的 `version` 与新版本一致、`url` 指向 `*-installer.exe`（走 ghfast.top 代理）。
- [ ] 旧版本客户端「检查最新」能收到新版本（updater 走 latest.json）。
- [ ] 新版本客户端首启弹出公告 toast；线上 `announcement.json` 的 `version` 已递增、首条是新版发布。
- [ ] 官网线上 badge / 版本行 / 两个下载按钮都指向新版本（`https://65tiankehan.github.io/Phoenix-DRX/`）。

## SPT Forge 发布（mod 页表单）

仓库：[`forge.sp-tarkov.com`](https://forge.sp-tarkov.com/)。首次建 mod 之后，每版只需 Create Mod Version。

**当前状态**：已于 2026-11-19 随 v0.2.4 上线对外可见（GUID `com.65tiankehan.phoenixdrx`，Tools / MIT，SPT 约束 `~4.1.0`）。此后每版流程：bump → 打 tag → CI 出 zip → Create Mod Version 填 zip 直链 + 同文件 VirusTotal → Publish Date 点 Now → 回本页历史表记一行。

**两个 Description 别填混**：mod 主页正文来自「Create Mod → Description」（长期信息，源文件在 [docs/forge/mod-description.md](../forge/mod-description.md)，改完整段粘过去）；每一版改了什么填「Create Mod Version → Description」。Forge 没有 tab 组件，SVM 那排导航是 Markdown 锚点链接，不是真 tab。

| 字段 | 填法 |
| --- | --- |
| Mod GUID | `com.65tiankehan.phoenixdrx`（**必填**，`Required for SPT 4.0.0 and above`） |
| License | MIT（仓库根已有 `LICENSE`） |
| Category | Tools |
| Show Cheat Warning | 勾上（存档编辑器属同类功能） |
| Download Link | 上面那个 **zip 直链**，不能填 exe |
| SPT Version Constraint | `~4.1.0`（自动匹配 4.1.0–4.1.6；数据层按 4.1.6 校准，不替 4.0/4.2 背书） |
| VirusTotal Links | **传 zip**（不是 exe），至少 1 条，哈希要与 Download Link 那个文件一致 |
| Fika Compatibility | 不兼容 |
| Publish Date | 点 **Now** 才会上线；留空＝一直是草稿 |

已知限制：Download Link 指向自解压安装器，不符合 Forge 的 mod archive 结构规范，所以页面上 **Install 按钮不会生效**，玩家只能点 Download。Description 里要写明「先把 zip 解压，再运行里面的 installer.exe」。

## 〇、先澄清一个命名误会

用户把子项目命名为 **DRX-NSIS**，但「方案 2（完全自研安装器）」**全程不使用 NSIS**——NSIS 是 Tauri 现成的打包工具（档一方案的主角）。自研安装器的技术本体是：

> **一个独立的 Tauri 薄窗程序 + Rust 落盘逻辑**（复制文件 / 写注册表 / 建快捷方式），视觉与主程序同一套 `--phx-*` token。

建议命名为 **DRX-Setup**（或 DRX-Installer）；目录名同理 `installer/` 或 `drx-setup/`。若用户坚持 DRX-NSIS 这个名字也无妨（纯代号），但文档层面需避免误导后人以为里面跑了 NSIS。**本方案按「不用 NSIS」展开，若拍板时想换回档一（NSIS 定制向导）随时可退。**

## 一、目标与复用设计（用户核心诉求）

**目标**：双击安装包后出现 Phoenix 风格的自有安装界面（暗色沉浸、品牌一致），替代 Windows 原生向导。

**复用设计（给后续项目）**：安装器做成**配置驱动的模板**——

- `installer-config.json`（或 toml）：应用名、主程序 exe 名、发布者、版本、图标、主题色引用、默认安装目录、是否需要 WebView2、静默参数等；
- 安装器前端读取配置渲染 UI，Rust 侧执行通用安装流程；
- 新项目接入 = 换配置 + 换图标 + 换载荷，代码零改动（或极小改动）。

这就是「积攒一套，多项目复用」的落点：**一套安装器骨架 + 每项目一份配置**。

## 二、技术调研结论（逐项）

### 2.1 载荷：安装包里怎么带上主程序

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| **A. 追加式自解压（推荐）** | 安装器 exe 构建完后，CI 把主程序产物 zip **追加到 exe 尾部**（zip + 8 字节偏移量 trailer + 魔数）；运行时读自身 exe、按 trailer 定位、解压落盘 | 安装器 GUI 与载荷**解耦**：换载荷不用重编安装器；CI 一条命令拼接；zip 用 `zip` crate 读取。经典自解压模式，成熟可靠 |
| B. `include_bytes!` 编译期内嵌 | zip 作为资源编进安装器二进制 | 简单但每次换载荷都要重编安装器；编译内存开销随载荷涨 |
| C. 安装时联网下载 | 安装器只做壳，现场下载主程序 | 依赖网络（与更新链镜像逻辑可复用），离线场景失败；首推组合 A，C 可作将来「在线精简版」扩展 |

**取舍**：A。安装器本体质变小（~5MB Tauri 壳），载荷 4–8MB zip 追加，总包与现在 NSIS 包同量级。

### 2.2 安装落盘：per-user 模式（与现状对齐）

- **装到 `%LOCALAPPDATA%\Programs\<AppName>\`**（Tauri NSIS 默认同为 per-user，**无需管理员权限**，与现有用户习惯一致）；
- 写「添加/删除程序」注册表项（exe 安装器的标准做法）：
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\<AppId>`，键值至少含 `DisplayName / DisplayVersion / DisplayIcon / Publisher / UninstallString / NoModify=1 / NoRepair=1 / EstimatedSize`；
- 开始菜单快捷方式 + 可选桌面快捷方式（安装界面勾选，默认勾开始菜单、桌面由用户选）；
- 快捷方式创建用 Rust：`windows` crate COM（`IShellLinkW` + `IPersistFile::Save`，微软 Shell Links 官方路径），或纯 Rust crate `mslnk` / `lnks`。**倾向 COM 直写**（工作目录、图标、参数全可控，不引入小众 crate 的维护风险）。

### 2.3 WebView2 运行时（自研安装器必须自己管）

NSIS 模板内置了 WebView2 引导，自研后要自己来，按微软官方口径：

1. **检测**：读注册表 `pv` 值——`HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}`（机器级）与 `HKCU\Software\Microsoft\EdgeUpdate\Clients\{...}`（用户级），`pv` 存在且 ≠ `0.0.0.0` 即已装；
2. **兜底**：注册表可能缺失（WebView2Feedback #2019），最终以 `GetAvailableCoreWebView2BrowserVersionString` API 调用为准；
3. **补装**：缺失时静默运行 Evergreen Bootstrapper（微软官方分发，免费再分发），UI 显示「正在准备运行环境」。

Win10/11 现状 WebView2 普及率极高，此分支大概率走不到，但**必须做**（否则裸机用户装完跑不起来）。

### 2.4 卸载：同一 exe 的第二人格

- 安装时把安装器自身复制为安装目录下 `Uninstall.exe`（带内置标记，启动即进卸载模式）；
- 卸载流程：提示关掉主程序 → taskkill 兜底 → 删快捷方式 + 删注册表 Uninstall 键 → 删安装目录；
- **自删除难题**（卸载中 exe 删不掉自己）：经典解法——卸载器退出前 spawn 独立 `cmd /c timeout 2 & rmdir /s /q "<安装目录>"`，延迟删目录；这是 per-user 自研卸载器的标准操作；
- 个人数据（`%APPDATA%` 下的存档/配置）默认保留，界面给可选勾选「同时删除个人数据」（备份过的存档放本地备份目录，卸载弹窗要提醒）；
- 卸载器**不做 GUI**（或仅一个确认 Dialog），系统「添加/删除程序」里点卸载 → 确认框 → 跑完。控制面板场景用户预期就是原生确认框，符合直觉且省一套稿图。

### 2.5 与现有更新链的兼容（关键设计约束）

tauri-plugin-updater 在 Windows 上下载安装包后调 `update.install(bytes)`，按 `tauri.conf.json` 的 `windows.installMode`（现为 passive）传 **NSIS 风格参数**（`/S` 静默等）。两条路：

- **路 A（推荐）**：自研安装器**兼容 NSIS 参数**——接受 `/S`（静默：默认目录、无 UI、装完直接退出），updater 链路零改动无缝续用；
- 路 B：updater 改走自研协议（改 Rust 安装调用），侵入大。

**取 A**：安装器解析 `/S` 走静默分支。静默模式同时服务「社区求静默安装」场景（`setup.exe /S` 是 NSIS 用户肌肉记忆）。

### 2.6 签名与 CI

- 现状：安装包只有 updater 的 minisign 签名（`.sig`），**无 Authenticode 代码签名**。自研安装器维持同现状（后续买证书另议，不阻塞）；
- CI（`release.yml`）：`tauri build` 出主程序 → zip 载荷 → **拼接到安装器 exe** → 产 latest.json（url 指向新安装器）→ 发布。安装器 exe 本体由独立 crate 构建并缓存，载荷变更不触发重编；
- MSI 是否保留：NSIS/MSI 双格式停掉，只发自研安装器（减少维护面）；过渡期可三格式并存一个版本观察。

## 三、工程结构（cargo workspace 成员）

```
Phoenix-DRX/
  src-tauri/          # 主程序（现状不动）
  installer/          # DRX-Setup（新增 workspace 成员）
    src-tauri/        #   Tauri 2 薄窗壳（420 宽，复用 --phx-* token）
    installer-config.json   # 复用模板的配置单一来源
    scripts/append-payload.mjs # CI/本地：zip 主程序产物 + 拼接 trailer
  docs/prototypes/    # 安装器稿图（下一步）
```

- 安装器 UI 复用主项目 token（`--phx-*` 值拷入安装器自己的 css，token 单一来源铁律按项目隔离执行——跨仓引用不现实，**在安装器 crate 内另立 token 块并注明来源**）；
- 视觉语言沿用：实心底薄窗、P 品牌位、三段式（欢迎/安装中/完成）+ 卸载确认。

## 四、风险与已知坑

1. **卸载自删除**：延迟 cmd 删目录方案在「用户手贱快速打开安装目录」等极端时序下可能残留空壳目录（无害）；VSCode 等一线产品也用类似妥协；
2. **HKCU Uninstall 键**：静默安装在别的账户上下文跑会写错 HKCU（SCCM 场景坑），本项目是个人玩家工具，风险低，文档标注即可；
3. **WebView2 per-user 安装静默消失**（WebView2Feedback #2019）：检测逻辑做成注册表 + API 双通道，别只信注册表；
4. **杀软误报**：自解压拼接 exe 是启发式误报高发形态（追加数据段）。缓解：拼接后 zip 目录结构规整、无加壳无加密；真被误报再考虑改 `include_bytes!` 内嵌（B 方案）换编译指纹。**这是本方案最大的不可控外部风险**，需真机 + 常见杀软实测；
5. **安装器本身是 Tauri 应用**：也要过 WebView2 检测——鸡生蛋问题。解法：安装器壳极小，若 WebView2 缺失，安装器退化为**纯 Rust 无 GUI 模式**（同一 exe 无 WebView2 时走 console/极简 msgbox 流程），保证任何机器都能装。

### S2/S3 真窗口实测坑（三条，均 2026-10-24）

1. **serde camelCase 对齐（复发）**：Rust `LaunchInfo` 输出 `defaultDir`，前端按 `default_dir` 读 → undefined → `slice` 炸、整个初始化中断（所有按钮监听全死）。与主项目 2026-10-18 设置页事故同款——**安装器子项目同样适用「前端字段名以 serde 输出为准」铁律**。自救手段：页面加 `showFatal` 错误上屏（error + unhandledrejection 双通道），安装器无 devtools 常开场景，出错必须可见。
2. **全出血透明窗禁挂 box-shadow**：`--phx-shadow-win` 是「窗内卡片」用的；透明窗上阴影落不到窗外、被窗口边界硬裁成底部方形半透明带（亮壁纸上显形）。修法：`.suwin` 不挂阴影。
3. **无边框透明窗三件套**：`transparent: true` + `shadow: false`（Tauri 默认 true！系统方形窗影裁不掉，四角残影）+ DWM `DWMWCP_ROUND` 请求，缺一不可。主程序薄窗走 Rust builder 有显式 `.shadow(false)`，**配置式窗口（tauri.conf）必须手动写 `"shadow": false`**。
